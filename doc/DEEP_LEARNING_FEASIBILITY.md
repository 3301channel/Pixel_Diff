# Pixel-Diff 深度学习方案可行性论证

## 1. 结论

Pixel-Diff 可以引入深度学习识别方法，但不建议在当前阶段直接用端到端大模型替代现有像素差分流程。更可行的路线是采用“传统图像算法召回 + 轻量深度学习复核”的混合架构：

```text
PDF 渲染 / 图像读取
  -> 颜色过滤
  -> SIFT 配准
  -> 自适应二值化
  -> XOR + 形态学差分
  -> 候选差异区域
  -> 轻量深度学习模型复核
  -> 坐标、置信度、可视化报告
```

这种路线能够兼顾低算力和较高准确率：

- 低算力：深度学习只处理候选小区域，不处理整页高分辨率图像。
- 高准确率：传统算法保证高召回，深度学习负责过滤残影、扫描噪声、签名线、整行文字边缘误差等误判。
- 可解释：仍输出像素坐标、残影图和人工复核报告，不把模型判断当作最终结论。
- 可渐进：可以作为实验开关接入，不破坏当前 MVP 主流程。

## 2. 为什么不建议直接端到端替换

本项目输入通常是 300 DPI 的 PDF 页面，单页可能达到 2500x3500 像素以上。若直接用深度学习模型整页检测，会遇到几个问题：

1. 算力压力大：整页图像分辨率高，CPU 推理较慢，GPU 部署成本高。
2. 标注成本高：端到端检测需要大量页级标注，包括新增、删除、修改和噪声样本。
3. 泛化风险高：合同模板、扫描质量、字体、印章、签名、纸张形变差异很大。
4. 可解释性下降：模型直接输出“有差异”不如坐标和残影图便于人工复核。
5. 法务场景风险高：系统定位是机器筛查，不能把深度学习输出包装成确定性结论。

因此，更稳妥的方式是保留当前传统算法作为主召回链路，把深度学习放在候选区域复核阶段。

## 3. 推荐总体架构

### 3.1 第一阶段：传统算法高召回

继续使用当前流程：

- PDF/DOCX 渲染为标准图像。
- HSV 过滤红章、蓝色签字。
- SIFT + FLANN + Lowe 比率测试 + RANSAC 完成全局配准。
- 自适应二值化处理扫描图。
- XOR 差分定位像素变化。
- 形态学去噪和连通域提取候选区域。

该阶段的目标是“尽量不要漏掉真实差异”，允许有一定误判。

### 3.2 第二阶段：轻量模型复核

对每个候选区域裁剪局部 patch，例如：

```text
模板 patch
待检 patch
残影 patch
候选框几何特征
```

输入轻量模型，输出：

```json
{
  "is_real_difference": true,
  "confidence": 0.91,
  "reason_type": "text_change"
}
```

建议分类类型：

- `text_change`：疑似真实正文变化。
- `alignment_residual`：配准残影。
- `scan_noise`：扫描颗粒或孤立噪点。
- `line_residual`：签名线、表格线、下划线残影。
- `stamp_or_signature`：印章或签字残留。
- `uncertain`：模型不确定，保留给人工复核。

### 3.3 第三阶段：人工复核友好输出

最终报告不只显示“模型认为真/假”，还应显示：

- 候选区域坐标。
- 模型置信度。
- 传统算法分数或规则命中情况。
- 残影图。
- 原始 patch 和待检 patch。
- 是否被模型过滤。

这样可以保持审计可追踪。

## 4. 可选深度学习方案

### 4.1 Patch 级二分类模型

这是最推荐的第一步。

输入：

- 模板局部图。
- 待检局部图。
- 残影局部图。

输出：

- 真实差异 / 误判。

模型可以很小，例如 MobileNet、ShuffleNet、EfficientNet-lite 或自定义轻量 CNN。输入尺寸可以控制在：

```text
64x64
96x96
128x128
```

优点：

- 算力低。
- 标注成本相对低，只需标候选框真假。
- 与现有流程结合简单。
- 可以直接解决当前最痛的误判过滤问题。

缺点：

- 只能判断候选区域，不能发现传统算法完全漏掉的差异。

适合本项目当前阶段。

### 4.2 Siamese 相似度模型

Siamese 网络输入模板 patch 和待检 patch，输出两者是否等价。

结构：

```text
template_patch -> shared CNN -> embedding_a
candidate_patch -> shared CNN -> embedding_b
distance / concat -> classifier
```

优点：

- 天然适合“两个局部图是否一致”的任务。
- 对模板变化较多的场景更稳。
- 可以学习字体粗细、轻微偏移、扫描噪声与真实改动之间的区别。

缺点：

- 训练数据需要覆盖足够多的相似但不相同样本。
- 对小标点、空格、数字变化要重点采样，否则容易误判。

推荐作为 Patch 二分类模型的升级方向。

### 4.3 OCR 辅助复核

OCR 不建议整页执行，建议只对候选区域执行。

使用方式：

1. 传统算法定位候选区域。
2. 对候选区域向外扩展一定边距。
3. 分别 OCR 模板 patch 和待检 patch。
4. 对 OCR 文本做轻量比对。
5. 只把 OCR 结果作为辅助信息输出给人工。

优点：

- 对“数字变化、文字替换、空格变化”有解释价值。
- 可以帮助人工快速理解差异。

缺点：

- OCR 对扫描质量、字体、中文标点、表格线敏感。
- OCR 错误不能作为最终判断。

建议定位为“候选文本提示”，不要作为唯一判定依据。

### 4.4 文档版面模型

版面分析模型可以识别正文、表格、页眉、页脚、签章栏等区域。

在本项目中更适合用于：

- 自动生成 ROI 忽略区。
- 跳过签名栏、印章栏、页脚噪声区。
- 对正文区域和非正文区域使用不同阈值。

但它不是第一优先级，因为当前项目的主要问题是候选差异误判，而不是缺少版面分区。

## 5. 低算力设计原则

### 5.1 不跑整页模型

深度学习只处理传统算法产生的候选区域。假设一页有 50 个候选框，每个 patch 为 96x96，则模型总输入量远低于整页 300 DPI 图像。

### 5.2 先规则过滤，再模型复核

建议顺序：

```text
候选区域
  -> 面积、宽高比、密度等规则过滤
  -> 局部相似度过滤
  -> 深度学习复核
  -> 低置信度保留人工复核
```

这样模型只处理更难判断的样本。

### 5.3 使用 ONNX Runtime

训练可以用 PyTorch，部署建议导出 ONNX：

- CPU 可运行。
- 便于 Java / Python 服务集成。
- 支持量化。
- 部署依赖相对可控。

### 5.4 INT8 量化

模型训练完成后可做动态量化或静态量化，将 FP32 模型转为 INT8。

预期收益：

- 模型体积更小。
- CPU 推理更快。
- 内存占用更低。

需要验证：

- 小标点、空格、细笔画变化是否因量化丢失。
- 低质量扫描图上的召回率是否下降。

### 5.5 批量推理

候选 patch 可以按页批量送入模型，例如一次推理 16 或 32 个 patch。这样比逐个 patch 调用模型更高效。

## 6. 训练数据设计

### 6.1 样本来源

可以从当前项目运行结果中构建训练集：

- `document1`、`document2` 等测试 PDF。
- 每次人工确认后的真实差异和误判差异。
- 真实扫描件、不同 DPI、不同打印机、不同拍扫质量。

每个候选区域保存：

```text
template_patch.png
candidate_patch.png
ghost_patch.png
region.json
label.json
```

### 6.2 标签设计

最小标签：

```json
{
  "label": "real"
}
```

更推荐：

```json
{
  "label": "false_positive",
  "reason": "alignment_residual"
}
```

原因类别建议：

- `real_text_change`
- `real_space_change`
- `real_number_change`
- `alignment_residual`
- `scan_noise`
- `line_residual`
- `stamp_signature_noise`
- `uncertain`

### 6.3 数据增强

为了提升模型泛化能力，可以对训练 patch 做轻量增强：

- 轻微平移。
- 轻微旋转。
- 模糊。
- 亮度变化。
- 对比度变化。
- 纸张背景噪声。
- 细微膨胀/腐蚀，模拟打印粗细变化。

注意不要增强过度，否则会把真实差异也学成噪声。

### 6.4 负样本重点

当前项目最需要模型学习的负样本包括：

- 文字红/青边缘残影。
- 签名线残影。
- 页面底部孤立噪点。
- 整行文字残影大框。
- 印章和签名过滤后的残留。

这些比随机负样本更有价值。

## 7. 准确率目标

本项目应优先保证召回率，再优化误报率。

建议指标：

```text
真实差异召回率 >= 98%
误报过滤率 >= 50%
低置信度保留率可接受
单页 CPU 推理增加耗时 <= 500 ms
```

解释：

- 漏检真实差异比多报误判更严重。
- 模型不确定时应保留给人工，不应强行过滤。
- 深度学习模块的目标是减少人工负担，不是替代人工裁决。

## 8. 推荐落地路线

### 阶段一：数据闭环

目标：先收集可训练数据，不急于训练模型。

工作内容：

1. 在报告中增加人工标注结果导出。
2. 对每个候选框保存 patch。
3. 建立 `real / false_positive / uncertain` 标签。
4. 累积至少数千个候选区域样本。

验收标准：

- 能从历史报告生成训练集。
- 每个样本可追溯到原 PDF、页码、区域坐标。

### 阶段二：轻量 Patch 分类器

目标：训练第一个低算力复核模型。

建议输入：

```text
ghost_patch: 96x96x3
region_features: area, width, height, aspect, density, local_iou
```

也可以使用三路输入：

```text
template_patch
candidate_patch
ghost_patch
```

输出：

```text
real / false_positive / uncertain
```

部署方式：

- PyTorch 训练。
- 导出 ONNX。
- Python 侧用 ONNX Runtime 推理。

验收标准：

- 已知样本不漏掉真实差异。
- 明显减少 `document1`、`document2` 中的残影误判。
- CPU 单页增加耗时可控。

### 阶段三：Siamese 模型

目标：提升相似文本、空格、数字变化的判断能力。

输入：

```text
template_patch + candidate_patch
```

输出：

```text
same / different / uncertain
```

验收重点：

- 空格变化。
- 标点变化。
- 单数字变化。
- 中文相似字变化。
- 字体粗细变化不误报。

### 阶段四：区域 OCR 辅助

目标：只对模型认为真实或不确定的候选区域做 OCR。

输出给报告：

```text
模板候选文本
待检候选文本
OCR 置信度
文本差异提示
```

注意：OCR 只作为辅助展示，不作为最终结论。

## 9. 与当前算法的关系

深度学习模块不应替代当前模块，而应作为后处理复核层。

建议保留以下开关：

```yaml
deep_learning_filter_enabled: false
deep_learning_model_path: models/patch_filter.onnx
deep_learning_confidence_threshold: 0.90
deep_learning_uncertain_policy: keep
```

默认策略：

- 模型高置信度判断为误判：过滤。
- 模型高置信度判断为真实：保留。
- 模型低置信度：保留给人工复核。
- 模型加载失败：回退到当前传统算法结果。

这样可以保证工程稳定性。

## 10. 风险分析

### 10.1 数据不足

深度学习效果高度依赖数据。若训练样本只来自少量模板，模型可能记住模板特征，而不是学习差异规律。

缓解措施：

- 收集不同合同、不同扫描质量、不同字体样本。
- 按模板维度划分训练集和测试集，避免同模板泄漏。

### 10.2 漏检风险

模型过滤误判时可能误删真实差异。

缓解措施：

- 高置信度才过滤。
- 低置信度保留。
- 真实差异召回率作为第一指标。
- 引入人工复核回流机制。

### 10.3 部署复杂度

引入模型后会增加依赖和模型文件管理。

缓解措施：

- 使用 ONNX Runtime。
- 模型文件版本化。
- 配置开关默认关闭。
- 模型加载失败时自动回退传统流程。

### 10.4 可解释性

模型输出可能不如规则直观。

缓解措施：

- 报告中显示模型置信度和保留/过滤原因。
- 保留原始 patch、残影 patch 和传统特征。
- 不把模型输出作为最终法律结论。

## 11. 算力预估

以低算力 CPU 场景估计：

```text
每页候选框数量：20 到 100
patch 尺寸：96x96 或 128x128
模型类型：轻量 CNN / MobileNet 类
推理方式：ONNX Runtime CPU 批量推理
预计额外耗时：数十到数百毫秒级，视 CPU 和候选框数量而定
```

如果候选框过多，可以增加前置规则过滤，或只对面积和残影规则无法判断的区域执行模型。

## 12. 推荐方案

综合低算力和高准确率要求，推荐路线如下：

```text
短期：
  当前传统算法 + 人工标注闭环 + patch 数据集导出

中期：
  轻量 Patch 分类器过滤误判
  ONNX Runtime CPU 部署
  高置信度过滤，低置信度保留

长期：
  Siamese 相似度模型 + 区域 OCR 辅助
  ROI/版面分析降低非正文区域噪声
```

不推荐：

- 一开始就整页深度学习检测。
- 一开始就使用大模型 OCR 全文比对。
- 让模型直接输出最终篡改结论。

## 13. 最终判断

本项目可以引入深度学习，并且可以兼顾低算力和高准确率，但前提是采用混合架构：

```text
传统算法负责召回
轻量模型负责复核
人工负责最终裁决
```

这种方案最符合当前项目目标，也最容易从现有代码平滑演进。
