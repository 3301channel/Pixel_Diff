# Pixel-Diff 项目开发指南

## 1. 项目目标

Pixel-Diff 用于比对“审批通过的电子 PDF”与“打印、签署后形成的扫描件”，识别正文中的新增、删除和修改，并输出可供人工复核的差异坐标与标注图。

项目遵循“机器筛查、人工裁决”原则：系统提供疑似差异，不直接给出法律意义上的篡改结论。

### 1.1 MVP 目标

- 将 PDF 页面按统一 DPI 渲染为标准图像。
- 过滤红色印章和蓝色签字笔迹。
- 使用 SIFT、FLANN、RANSAC 和单应性矩阵完成全局配准。
- 对扫描图和模板图进行二值化、异或差分和形态学降噪。
- 输出差异区域的结构化坐标和可视化标注图。
- 对输入、配准失败和输出异常给出明确、可追踪的错误。

### 1.2 后续生产阶段目标

- 基于版面分析配置签章栏等 ROI 忽略区。
- 使用局部网格与薄板样条处理非线性纸张形变。
- 自动估计笔画宽度并补偿打印粗细差异。
- 仅对差异区域执行 OCR，输出修改前后的候选文本。
- 支持多页任务、批处理、指标监控和审计记录。

以上能力不属于 MVP 强制验收范围，除非后续需求明确变更。

## 3. 开发约束

### 3.1 技术与输入约束

- 使用 Python 3.11 或更高版本。
- 核心图像处理使用 OpenCV 和 NumPy。
- 内部图像统一为 OpenCV BGR 或单通道 `uint8`；函数必须注明颜色空间。
- 同页模板和扫描图在差分前必须统一到模板尺寸。
- PDF 默认按 300 DPI 渲染；其他 DPI 必须通过配置显式传入。
- 不允许把文件读取失败当作“无差异”。

### 3.2 算法约束

- MVP 配准使用 SIFT + FLANN + Lowe 比率测试 + RANSAC 单应性。
- 有效匹配点少于配置阈值、描述子为空或单应性不可用时必须终止任务。
- 色彩过滤只能作用于配置的 HSV 范围，并保留可关闭开关。
- 边缘裁剪宽度必须小于图像宽、高的一半。
- 所有阈值均集中在配置模型中，不得散落为无说明的魔法数字。
- 差异区域必须在原图坐标系内，使用左上角原点和像素单位。
- 区域输出按 `y、x、面积降序` 稳定排序，不依赖 OpenCV 轮廓返回顺序。

### 3.3 工程约束

- `engine.py` 只负责编排；算法模块保持单一职责并可独立测试。
- 公共函数、模型和异常必须有类型标注及简明文档字符串。
- 禁止使用根日志配置 `logging.basicConfig` 污染调用方；使用模块级 logger。
- 默认不得覆盖输入文件；输出目录不存在时按接口约定创建或明确报错。
- 日志不得记录合同正文、OCR 全文或图像二进制内容。
- 可重复运行必须得到相同的区域顺序和等价坐标结果。
- 每次修复缺陷时补充能复现该缺陷的自动化测试。

### 3.4 范围约束

- MVP 不承诺检测语义等价、字体替换、复杂表格结构变化或肉眼不可见的元数据变化。
- 红章和蓝色签名默认作为噪声过滤；黑色签名不能仅凭 HSV 可靠识别。
- ROI、局部网格校正、笔画补偿和 OCR 属于扩展模块，不得写成当前已实现能力。
- 任何涉及司法、合规或合同效力的判断必须由人工完成。

## 4. 变更原则

1. 先修改规格和验收标准，再改变公共行为。
2. 新算法必须提供关闭开关，并与当前基线做同一数据集对照。
3. 精度改进不得以未披露的大幅性能下降为代价。
4. 未达到验收标准的实验能力必须标记为实验性，不能成为默认路径。
